# Switter

Switter — автономный блог на PHP. Записи по-прежнему хранятся в `posts.json`, вложения — в `uploads/`, архивы — в `archive/*.html` и `archive/uploads/`. Настройки хранятся в служебном файле `.switter-config.php`. СУБД не нужна.

## Концепция проекта

Значительной части интернет-пользователей не нравится, как традиционные социальные сети собирают данные.
Многих также не устраивает политика администраторов социальных сетей, которые могут заблокировать страницу по любому, даже самому незначительному поводу.
Некоторые люди заводят отдельные блоги ради большей свободы, однако управлять такими блогами бывает неудобно — особенно с мобильных устройств.
Данный проект призван объединить свободу, которую дают отдельные блоги, с удобством использования, свойственным социальным сетям.

## Установка

1. Разместите файлы Switter в каталоге сайта с PHP. Нужны расширения `mbstring`, `fileinfo` и `zip`. Установщик принимает стабильные выпуски PHP от 8.2.35, 8.3.36, 8.4.27 или 8.5.12 в соответствующих ветках, а также более новые стабильные ветки.
2. Дайте пользователю PHP право записи в каталог блога, `uploads/` и `archive/`. Включите HTTPS и отключите `display_errors` на публичном сервере.
3. Откройте `install.php`, выберите язык и нажмите кнопку применения языка. Затем задайте логин, пароль и название блога. Для смены языка или пароля после установки используйте настройки в `admin.php`.

Включён файл `.htaccess` для Apache с `mod_rewrite` и разрешённым `AllowOverride FileInfo`. Для Nginx добавьте следующие правила в блок `server`. Для установки в подкаталоге добавьте его префикс во второе правило.

```nginx
location ~ (^|/)\.switter- { deny all; }
location ~ ^/(lib|locales|tools)/ { deny all; }
```

Разместите правила перед общим регулярным правилом PHP и передайте заголовок авторизации в блоке FastCGI через `fastcgi_param HTTP_AUTHORIZATION $http_authorization;`, если конфигурация его не передаёт.

### Обновление существующего блога

1. Сохраните полную копию прежнего каталога **вне корня сайта** и закройте публичный доступ на время обновления.
2. Скопируйте новые файлы приложения. Сохраните действующий `posts.json`, содержимое `uploads/`, файлы `archive/*.html` и каталог `archive/uploads/`. Файл `archive/index.php` обновите, стили при необходимости объедините со своими.
3. До открытия доступа выполните из нового каталога `php tools/migrate-legacy.php /путь/к/старой-копии` от имени пользователя PHP. Команда переносит исходный логин и хеш пароля, заголовок, описание и шапку, созданную прежним установщиком. Произвольные правки в шаблонах `index.php` и `admin.php` перенесите из старой копии вручную.
4. Проверьте вход в `admin.php` прежним паролем. Существующие записи и HTML-архивы читаются в исходном формате.

## Вложения и архивирование

У записи может быть одно вложение. JPG, PNG, WebP и GIF поддерживаются до 5 МиБ. Анимированные GIF сохраняются как есть. WebM поддерживается до 25 МиБ и до 60 секунд при наличии читаемой длительности. Для проверки WebM нужен `ffprobe` из FFmpeg и доступная функция PHP `proc_open`. Добавьте `ffprobe` в `PATH` процесса PHP или задайте абсолютный путь в переменной окружения `SWITTER_FFPROBE`.

Для полного лимита WebM установите `upload_max_filesize` не ниже `25M` и `post_max_size` выше этого значения, например `32M`. Учитывайте также лимит тела запроса веб-сервера или прокси. Веб-сервер должен отдавать `.webm` с типом `video/webm`.

При архивировании активные записи и вложения переносятся в HTML-архив. Вложение шапки и файлы, которые не принадлежат записям, остаются в `uploads/`. Текст поддерживает `**жирный**`, `*курсив*`, `__подчёркивание__`, `~~зачёркивание~~`, `[ссылку](https://example.com)` и обычные HTTP(S)-ссылки.

## Резервное копирование

В `admin.php` откройте «Резервное копирование и восстановление». ZIP-копия содержит активные записи, вложения, HTML-архивы, архивные вложения и публичные настройки блога, включая язык и содержимое шапки. При переносе на другой сервер сначала установите Switter и войдите в его админку. Восстановление заменяет содержимое и публичные настройки целевого блога. Логин, пароль и токен API берутся из настроек целевой установки. Код и пользовательские изменения шаблонов храните отдельно.

Принимаются ZIP-копии Switter с суммарным объёмом распакованных файлов до 1 ГиБ и не более 20 000 файлов. Серверные лимиты загрузки должны быть больше размера ZIP. Загружайте копии, созданные вами или полученные из доверенного источника, так как резервная копия содержит публикуемые HTML-архивы.

## API v1 для Android

Базовая конечная точка — `api.php?version=1`. Отсутствие параметра `resource` означает `posts`. Чтение открыто. Для записи создайте токен в разделе «Доступ к API» и передавайте его в заголовке `Authorization: Bearer <токен>` по HTTPS. Сохраните токен при создании. Выпуск нового токена заменяет прежний, а смена пароля отзывает действующий токен.

| Метод | Параметры запроса | Результат |
| --- | --- | --- |
| GET | `resource=blog` | Публичные настройки, язык, часовой пояс и медиа шапки |
| GET | `resource=posts&limit=20&offset=0&q=текст` | Активные записи от новых к старым. `q` ищет по заголовку и тексту, `limit` от 1 до 100 |
| GET | `resource=posts&id=ID` | Одна запись |
| POST | `resource=posts` | Публикация, ответ 201. Передайте JSON с полями `title` и `content` или multipart-форму с теми же полями и необязательным файлом `media` |
| DELETE | `resource=posts&id=ID` | Удаление записи |
| GET | `resource=archives` | Список HTML-архивов с полями `name` и `url` |
| POST | `resource=archives` | Перенос всех активных записей в новый HTML-архив, ответ 201. При пустой ленте ответ 409 |

Успешный ответ содержит `version` и `data`. В списке записей также есть `pagination` с полями `limit`, `offset`, `total` и `next_offset` (`null` на последней странице). Запись содержит `id`, `title`, исходный текст `content`, `created_at` в формате `YYYY-MM-DD HH:MM:SS` в часовом поясе из `resource=blog` и `media`. Медиа представлено как `null` или объект с полями `url` и `mime_type`. URL медиа и архивов относительны к каталогу `api.php`.

Ошибки содержат `error.code` для обработки в клиенте и локализованное `error.message` для отображения. Например, без токена запрос на публикацию вернёт HTTP 401 и код `api_unauthorized`.

```sh
curl 'https://example.com/blog/api.php?version=1&resource=posts&limit=10'

curl -H "Authorization: Bearer $SWITTER_TOKEN" \
  -F 'title=Новая запись' -F 'content=Короткое видео' -F 'media=@clip.webm' \
  'https://example.com/blog/api.php?version=1&resource=posts'
```

[Существующий Android-клиент](https://github.com/one-loner/Switter_Android) использует прежние HTML-формы и JSON-файл. Для поддержки WebM через нативный интерфейс клиенту потребуется перейти на API v1.
